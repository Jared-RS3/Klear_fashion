PROJECT OVERVIEW

Executive Summary

This revised proposal responds to Kliya's founder-issued MVP Integration & Technical Support Brief. Daybreak's role is to implement, validate and harden selected third-party integrations around the existing Kliya MVP. The core product build, product flows and visual system are not included.

The engagement is structured as a modular integration programme: approved providers are connected through a maintainable backend/API layer, external outputs are mapped into Kliya's internal structures, failure states are handled gracefully, and the final implementation is documented for future maintenance or provider replacement.

WHAT THIS ENGAGEMENT COVERS

  1. 01Integration architecture & backend foundation
  2. 02Body Intelligence / body measurement
  3. 03Virtual Try-On
  4. 04Garment / simulation / fit infrastructure
  5. 05PointAI validation & lightweight path
  6. 06Product ingestion / Garment Intelligence
  7. 07Affiliate commerce / creator attribution
  8. 08QA, security hardening, documentation & handover
→

The revised scope is estimated at 209 engineering hours at Daybreak's standard R1,100/hour rate — an estimated labour basis of R229,900. The commercial project fee is fixed at R230,000 for the scope defined in this proposal — the fixed price protects Kliya from hourly overruns, and the defined scope protects Daybreak from unbounded work; anything beyond it is priced separately via a written change request (see Workstream & Investment Breakdown).

WHAT IS BUILT

Scope of Work

  • Implement approved third-party APIs/SDKs into the existing Kliya MVP.
  • Build and harden the backend/API layer required for each approved integration.
  • Map provider inputs and outputs into Kliya's internal data structures.
  • Implement authentication, secure secret handling, request/response orchestration, retries, rate-limit handling, logging and graceful failure states where appropriate.
  • Test end-to-end data flow, document constraints and isolate provider-specific logic behind modular service boundaries.
  • Commit bespoke integration code to Kliya-controlled repositories and provide handover documentation.
